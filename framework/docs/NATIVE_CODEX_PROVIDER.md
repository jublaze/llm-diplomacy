# Native Codex CLI provider

`codex_cli` is an optional provider for controlled local experiments. Compatibility is checked against the installed npm package metadata for Codex CLI 0.162.1; the adapter does not launch the executable to verify its version. Follow the [official Codex CLI instructions](https://learn.chatgpt.com/docs/non-interactive-mode) to install it, then complete its supported ChatGPT login interactively before selecting this provider. The adapter uses the saved login through the existing `CODEX_HOME`; it never reads, exports, or copies authentication material. The bounded example in `config/examples/native_codex_cli_bounded_example.yaml` selects a live provider if executed and stops before a second provider attempt; it is not a dry-run or offline config. Supported reasoning efforts are `low`, `medium`, `high`, `xhigh`, and `max`.

Each provider request starts one new ephemeral CLI session in a fresh temporary working directory. The player prompt goes only through stdin. The adapter requests a strict outer envelope around the method's JSON result, explicitly sets top-level `web_search="disabled"`, requires a chronologically complete thread and turn, rejects tool-call and unknown events, caps prompt and streamed output sizes, applies a timeout, and cleans up the owned process tree on success and failure. After checking the outer envelope, it passes the inner content string unchanged to the runtime's JSON and method validation and bounded repair path. On Windows it creates the process suspended, assigns it to a kill-on-job-close Job Object, then resumes it before writing the prompt. On POSIX it starts a new process session and terminates the process group even if the leader has exited. It removes the temporary directory after success and failure. It makes no provider-level retries; the framework's existing bounded validation-repair behavior remains separately logged. CLI internal transport attempts and account quota are not observable guarantees.

The adapter disables the captured enabled tool features and applies a named read-only filesystem permission profile with network disabled. It ignores user configuration and rules, sets project-document loading to zero, replaces model instructions, disables memory and host-skill discovery, and supplies an empty MCP server map. It does not combine these settings with the legacy sandbox flag. A managed policy may reject or override the named profile. Provider and Codex execution tests use mocked subprocesses; a separate harmless Python child/grandchild smoke exercised Windows Job Object cleanup after the leader exited. No actual Codex invocation or isolation test has run, so these settings do not prove effective host enforcement. A failed explicit native selection stops at provider boot rather than silently substituting the fake backend.

Only model and reasoning effort are accepted as model-selection settings. Temperature, output-token limits, endpoint overrides, API-key variables, and price tables are rejected. The requested model and effort remain recorded. Captured `input_tokens`, `cached_input_tokens`, `output_tokens`, and `reasoning_output_tokens` are retained when reported; no total is synthesized. Codex CLI does not provide a trusted resolved model in the captured interface, so `resolved_model`, unreported usage, and USD cost remain unknown; no API price estimate is applied. Provider-attempt counts count adapter invocations, not hidden CLI network retries.

Historical adapter-validation note: this work made no Codex or model request and did not launch the then-planned 1912 experiment. The later `luna1912-1018-r2` Responses experiment completed in October 2026. That history does not establish current native-provider account access or authorize a new live run. Free-text reflections follow the selected runtime policy; the CLI's outer envelope does not impose the legacy reflection JSON contract on them.
