# Core event contracts v1

`ArtifactValidator` checks first-party event rows offline. It does not rewrite historical artifacts. Artifact `schema_version` remains `1.0`; optional `event_contract_version`, when present, must be `core_events_v1`. Unknown event types receive envelope checks only so later producers remain readable. Unknown provider-attempt kinds fail because each kind carries distinct accounting semantics.

| Stream | Registered first-party event families |
| --- | --- |
| `events.jsonl` | `game_initialized`, `game_started`, `phase_started`, `phase_completed`, `snapshot_committed`, `negotiation_tick_staged`, `negotiation_tick_committed`, `game_end_cleanup_applied`. Rows also require the event ID, game ID, nullable phase ID, and object payload. Phase start, nonterminal phase completion, and negotiation tick rows require a nonempty phase ID. Snapshot events require a snapshot ID. Nonterminal phase completion requires movement/retreat/adjustment plus snapshot ID; `game_end` requires a terminal result. Negotiation tick and cleanup payloads require nonnegative counters and participant IDs where emitted. |
| `experiment_events.jsonl` | Experiment lifecycle: `experiment_started`, `experiment_completed`, `experiment_stopped`, `experiment_error`, `systemic_provider_failure`. Game lifecycle/results: `game_started`, `game_completed`, `game_stopped`, `game_error`, `game_summary`, `observatory_generated`. Phase/resolution: `phase_started`, `phase_completed`, `orders_validated`, `board_resolution_summary`, `phase_resolved`. Invocation/elimination: `agent_invocation_started`, `agent_invocation_completed`, `agent_invocation_failed`, `agent_invocation_skipped_eliminated`, `eliminated_agent_final_cleanup_completed`, `power_eliminated`. Prompt/reflection/orders: `prompt_assets_loaded`, `prompt_check`, `reflection_generated`, `reflection_validated`, `reflection_fallback_applied`, `reflection_repaired`, `orders_generated`, `orders_repaired`, `orders_fallback_applied`, `relationship_snapshot`. Negotiation: `negotiation_tick_participants`, `messages_generated`, `message_dropped`, `message_committed`. Budget: `budget_state`, `budget_stop_triggered`, `budget_warning`, `budget_milestone`. Each of the 40 registered first-party types has a valid producer-shaped test sample and required/type checks; known enumerations such as lifecycle methods, phases, and stop policies are constrained. Both `orders_validated` variants require game and phase IDs. Budget state/stop rows require all producer-emitted nullable usage fields; budget state/stop game and phase IDs are optional, and legacy `budget_state` stop reason remains optional, all type-checked when present. |
| `budget_events.jsonl` | `budget_check`, `budget_exceeded`, `budget_usage_update`, `provider_error`. These nested payloads require game, phase, agent, and method context; usage-update totals require provider calls and all nullable token/cost totals. |
| `provider_attempts.jsonl` | `request`, `blocked`, `lifecycle`, `eliminated_skip`. Request and blocked rows require attempt index, provider object, and nullable response/usage fields. `cached_input_tokens` and `reasoning_tokens` are optional reported usage details. Blocked attempts cannot record a response or billed usage. Lifecycle rows require a fallback boolean. Eliminated skips retain common call context. |

## Compatibility

The contract preserves observed producer variants. `experiment_completed` accepts legacy `games_completed` or current `completed_games`; if both are present they must agree. Legacy `game_completed` may omit `winners`, and legacy `game_started` may omit `assignments`. Phase-start season/year and phase-completion snapshot IDs are optional because negotiation records omit them. `orders_validated` accepts either aggregate submitted/validated/invalid counters or the per-agent country, invalid reasons, and output path; both variants require game/phase context. A systemic provider failure may omit `phase_id` or set it to null. Budget state and stop rows may omit game/phase IDs; legacy `budget_state` rows may also omit `stop_reason`, but all rows require provider call count and nullable token/cost totals, while `budget_stop_triggered` requires a reason. Prompt checks are emitted only for LLM invocations and constrain method to the lifecycle method set. Invocation country and tick may be null; prompt metadata and logs remain optional where older emitters omit them, and current invocation output can explicitly set `prompt_checks` and `prompt_assets` to null. Provider-attempt `eliminated_skip` records retain their historical absence of request-only fields.

Counters are nonnegative integers, excluding booleans. Costs are finite nonnegative numbers; arbitrarily large integers are handled without aborting validation. Null usage means unknown. Post-elimination cleanup flags require the cleanup method. Terminal results constrain result kind, winner IDs, country entries, and stopped/partial consistency; stopped results require a nonempty stop reason, and legacy country entries may omit center counts. Country-map diagnostics use numeric entry positions and do not echo untrusted keys. `provider_error_details` may be null or an object because current runner records explicitly emit null when no detail object exists.

These checks validate record shape, not cross-file agreement, historical truth, or gameplay outcomes. Generated offline runner streams exercise the producer-to-validator path. Hand-authored producer-shaped samples cover every registered experiment family and variant; an AST check reconciles literal event names against emitter source. Malformed discriminators and rows return structured diagnostics without aborting later rows. Unknown event type strings remain envelope-only in event-bearing streams; unknown provider-attempt kinds remain invalid. Diagnostics use category `invalid_event_payload` and include file, JSONL line, and safe field path; raw prompts, messages, provider bodies, credential values, and untrusted country keys are not included.
